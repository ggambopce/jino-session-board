# Codex 교차검증

Codex CLI(`codex exec`)를 읽기 전용 샌드박스로 실행해 프로젝트 파일을 검토하게 하고,
판정과 지적 사항을 구조화된 결과로 받는다. Codex 는 파일을 고치지 않는다.

필요한 것: Codex CLI 설치와 로그인 (`codex login`). 검토는 사용자의 Codex 계정 한도를 쓴다.

## 실행

프로젝트 폴더에서 실행한다. 몇 분 걸릴 수 있으니 타임아웃을 넉넉히(10분) 준다.

```bash
node "${CLAUDE_SKILL_DIR}/scripts/codex-verify.mjs" --session "${CLAUDE_SESSION_ID}" [대상] [--focus "<중점>"]
```

대상은 사용자의 말에 맞춰 하나를 고른다.

| 사용자가 말한 것 | 대상 옵션 |
|---|---|
| 특정 파일이나 폴더를 짚었다 | `--paths src/pay.ts src/cart` |
| "방금 바꾼 것", "커밋 전 변경분" | `--diff` (기준을 말했으면 `--diff main`) |
| "이번 세션에서 네가 고친 것" | `--session-changes` |
| "프로젝트 전체" | `--all` |
| 아무 말 없음 | 옵션 없이 실행. git 변경분, 세션에서 고친 파일, 전체 순으로 스스로 고른다 |

사용자가 걱정하는 점을 말했으면 `--focus` 에 그대로 옮긴다 (예: `--focus "동시 요청에서 재고가 음수가 되는지"`).
다른 폴더의 프로젝트면 `--cwd <폴더>`, Codex 모델을 지정했으면 `--model <이름>`.
보낼 지시문만 미리 보려면 `--dry-run`.

## 결과를 다룰 때

1. 출력된 판정(통과, 고칠 점 있음, 불합격)과 지적 사항을 사용자에게 간추려 전한다. 심각도 높은 것부터.
2. Codex 의 지적을 그대로 믿지 않는다. 지적마다 해당 파일을 직접 읽어 맞는지 확인하고,
   맞는 것, 틀린 것, 판단이 갈리는 것으로 나눠 말한다. 이것이 교차검증이다.
3. 고치는 일은 사용자가 원할 때만 한다. 먼저 무엇을 고칠지 물어본다.
4. 결과는 `~/.claude/session-board/codex/` 에 저장되고 세션 보드의 「코덱스」 탭에 나타난다.

## 실패했을 때

| 종료 코드 | 뜻 | 할 일 |
|---|---|---|
| 2 | 대상을 찾지 못함 | 경로를 확인하거나 `--paths` 로 직접 지정 |
| 3 | Codex CLI 없음 또는 로그인 안 됨 | 사용자에게 설치와 `codex login` 을 안내. 대신 로그인하지 않는다 |
| 4 | Codex 가 결과를 내지 못함 | 출력된 마지막 로그를 사용자에게 전하고, 대상을 좁혀 다시 시도 |
| 5 | Codex 계정 사용 한도 | 한도가 풀리는 시각을 전하고 기다린다. 한도를 우회하지 않는다 |
